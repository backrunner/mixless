# ONNX Runtime + CoreML 接入与验证

2026-09-22；Apple M5 Max、18 logical CPUs、64 GiB、macOS 27 / Darwin 27 arm64。使用仓库固定 HTDemucs 与 Basic Pitch 权重、ort 2.0.0-rc.13 / ONNX Runtime 1.28。性能结果只覆盖本机和下述片段。

## 实现

macOS arm64 默认使用 CoreML MLProgram、CPUAndGPU。只在内存中为固定 HTDemucs 的两个 iSTFT ConvTranspose 添加等价的 `output_shape=[351232]`，将它们留给 ORT CPU。原文件及权重不改写。原始图直接用 CoreML 的 GPU/ALL/静态形状/基础图优化配置均约 24 s/7.8 s；profile 将主要耗时定位到包含逆频谱变换的子图。适配后合成单片段热推理为 0.36–0.38 s，CPU 约 0.93 s。

Basic Pitch 保持 CPU：MLProgram 编译报 `Required param 'pad' is missing`；NeuralNetwork 路径未测得收益；强制静态形状虽能加载，但 profile 显示全部节点仍在 CPU。因此不将注册成功误报为 GPU 加速。

`session.rs` 处理后端选择、注册/编译失败回退、运行出错/非有限值后 CPU 单次重试、可取消的编译锁及 profile。`coreml.rs` 处理固定图适配。编译缓存位于桌面 `stem-cache/.coreml`，按模型和适配/ORT/配置版本隔离；本机约 648 MiB。清理全部 stem 缓存会删除编译产物，单曲清理保留。诊断入口、环境变量见 [原生推理参考](../reference/native-inference.md)。

## 真实音频性能与输出

Release benchmark，CPU 4 线程，每组重复 3 次；取后两次平均，30 s 真实片段，包含分轨和两路音符推理，不包括模型加载和保存 WAV。未清空已有分轨缓存也不会命中它：benchmark 直接调用原生推理接口。

| 片段 | CPU | CoreML + CPU | 加速 |
| --- | ---: | ---: | ---: |
| Lost & Found，100–130 s | 5.502 s | 2.918 s | 1.89× |
| In The Echo，100–130 s | 5.371 s | 2.814 s | 1.91× |

CoreML 已编译缓存重载分别为 1.749 / 1.563 s。首次 debug 端到端加载测得 28.801 s（含校验、转换及编译），不能把热运行加速当作首次短片段总耗时收益。独立 145–175 s 片段 debug 热运行由约 6.57 s 降至 2.79 s。

最后一轮 WAV 相对 CPU 的最大采样差：Lost & Found 为 1.84e-4，In The Echo 为 6.14e-4。额外对 In The Echo 连续推理 10 次，每次对比 CPU 的全部采样，最大误差均小于 1e-3，最坏为 8.70e-4。CoreML 输出不是逐比特确定的；早期重复运行中曾出现音符总数 225/228 的变化，145–175 s 片段也有少量音符结束边界变化（最大约 93 ms）。这些是数值近似与阈值解码差异，不声称音符事件完全等价。

ORT profile 确认 CoreML 子图确实执行，两个目标 iSTFT 节点实际分配给 CPU。Profile 证明 ORT 的分配；未用 Instruments 对 CoreML 内部每个算子的 GPU 执行或能耗做独立测量。未做试听验收，不把采样误差或残差当作主观音质评分。

## 验证

- `cargo test --locked --workspace --exclude mixless-desktop`：362 passed，16 ignored。首次在并行负载下有一个 yt-dlp 超时测试失败，后续完整重跑通过。
- `cargo test --locked -p mixless-desktop`：92 passed，3 ignored。
- `native_coreml_matches_cpu_and_unwritable_cache_falls_back` 显式运行通过：原始 CPU 与 CoreML 最大采样差 1.30e-4；适配后的 CPU 图与原始 CPU 图逐样本误差小于 1e-6；CoreML 必须实际启用；初始化失败、运行失败的持久 CPU 回退和取消均验证。
- `bundled_models_analyze_new_audio_offline_after_download_cache_cleanup` 显式运行通过：无下载，新音频实际分析与内置模型重新加载成功，下载模型目录未被填充。
- 桌面 `native_models_reach_default_preparation_sql_cache_and_planner` 使用 30 s 真实音乐显式通过：默认队列、SQL、三轨发布、播放与规划均覆盖。基础播放并发推理 p99 0.066 ms；双碟声部 + keylock/pitch + 新推理 p99 0.295 ms，相对 128-frame / 2.667 ms 时限。这里是离线 render 回调测量，不是物理声卡 loopback 或 UI 观感验收。
- Intel macOS `cargo check --locked -p mixless-stems --all-targets --target x86_64-apple-darwin` 通过。使用 rustup stable 的 rustc 和独立 target 目录，Homebrew rustc 本身没有该 target 的标准库。
- `./dev.sh --build` 通过，开发包更新为 `target/app/Mixless.app`。独立带模型包的 `--check-bundled-models` 离线加载通过；未发布、安装到 Applications 或启动 UI。
- 变更 Rust 文件格式与 `git diff --check` 通过。

本地原始证据：`target/coreml-audit/` 下的 `native/`、`release/`、`repeated/`、`parity.log`、`offline.log`、`playback.log`、`bundled.log`。实验用大体积编译缓存已清理，日志和 profile 保留。没有提交音频、模型或编译产物。
