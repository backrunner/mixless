## 使用与显示

选择播放列表会在后台准备分析和相邻曲对，包括末曲到首曲。点击顶部 **AUTO** 后，从当前在播曲继续；空碟从列表首个可播放条目开始。支持顺序及逐轮乱序循环。下一首在空闲碟盘提前载入，静音时设置接点、速度、key lock、可选移调和初始 EQ/filter。入碟开始播放时自动选中它。

仅开启 AUTO 且正在查看其所属列表时，全曲波形显示计划的 **IN / OUT** 和混音区间：上半部青绿色是进入窗口，下半部紫色是退出窗口，竖线标出边界。共享 `MixPlan::mix_windows` 从 gain、crossfader 和 stem 包络计算干声交换范围，排除静音准备及独奏恢复；瞬切显示点位，循环显示实际重复的源区间。这是控制包络窗口，不是对 EQ/filter、源音频静音或 FX 尾音的可听性测量。实际执行计划覆盖后台预估；重复条目按出现位置匹配，无法消除歧义时隐藏。预估邻接关系失效、关闭 AUTO、手动接管或切到其他列表后隐藏相应标记。编号 Cue 和 A/B 实际播放位置仍保留。

拖动整行调整的顺序存入 SQLite，列表刷新和重新导入会保留现有曲目的相对顺序，新曲追加到后面，删除的条目退出队列。重复曲目按出现次数保留。应用记忆选中的列表；正常退出会等待尚未完成的排序写入。

过渡条绑定引擎快照的精确 plan ID，显示源时间范围、完整计划技法、阶段、倒计时和实际控制值；瞬时 stem 开关不再改写技法名称。静音等待、完成退出、暂停和手动接管分别显示对应状态。手动接管后不继续展示已失真的窗口与阶段；计划结束后旧 tooltip 隐藏。PAUSE / RESUME 同时暂停和继续当前双碟计划；SKIP 完成交接。手动改变控制 lane 会接管该 lane；改变源时钟的 seek、BeatJump、reverse 或 jog 会取消当前计划。Cue / Play 关闭 AUTO 会话；手动换歌会保留队列意图并重新准备。关闭 AUTO 保留当前播放与控制位置。

## 音乐安排

- 混音起点来自测得的编曲、乐句与用户 Cue，不要求在 build-up/drop 前后固定多少小节。允许在高潮仍播放时提前铺入合适素材，最终退出不能截断已识别的高潮。高潮后的 break 可从真实边界开始混合。
- 普通叠混搜索实际乐句长度以及 4/8/16/24/32/48/64 小节等候选，窗口上限 128 小节。相容且可靠的长窗口有持续性评分；没有统一最小时长，也不为达到某个数字而跨越不合适的乐段。
- 当前普通、原调、保持速度及准备交接路径都失败后，自动前瞻路径才补搜缺失的 4–16 整小节 BeatBlend/LoopRoll 窗口。用户指定技法不走此补搜，已有有效方案保持优先；新增窗口仍通过全部原有安全检查。冷曲对代价继续使用原有有界搜索，补搜不写入它的候选缓存。当前 `ORDER_VERSION=28`。
- 前瞻选择保留已生成的原调、保持速度方案：出入点及最终速度、音高相同，不代表声部路由、EQ 或评分相同。完成速度恢复后，按精确的已建立入场、结束时间、速度和音高复用下一段预测；同状态且当前代价不更好的备选不会增加无效预测。
- 前景边界和桥接采样复用当前不可变分析的线性功率，保留原有取帧、采样密度、浮点累加顺序及安全规则。宽度试探的剪枝与局部增量评分实验未获得可靠提速，因此未保留。
- 独立宽度试探使用固定批次，CPU 保持原有评分、缓存和严格择优顺序。可选 `gpu-audit` 仅供离线 Metal 全评分对照，不参与方案选择或剪枝；默认应用不启用它。完整模式保留全部观察，尽力模式必须报告遗漏，GPU 数值接近不等于 planner 决策相同。
- 生产评分复用鼓声部变化无法修复的人声、调性及前景失败，键保留其余六条包络的全部精确端点；电平失败及有效分数仍使用完整形状键。AArch64 NEON 并行计算四条淡变包络，保留除法、运算顺序及严格择优规则；其他目标继续使用标量包络。见 [生产评分提速验证](../history/2026-11-12-planner-production-speed.md)。
- **DropCut** 需要完整出碟 build-up 直接衔接入碟 drop 的证据。结构和声音接点允许时，也可在一个完整 drop 后瞬切到另一首 break。瞬切计划长度为零，不提前一小节启动入碟；引擎仍做短去点击处理。
- Bass Swap 是持续重叠中的低频交接阶段，不等于整个混音时长。高频、低频、中频、Level、filter 和 crossfader 可分阶段迁移，包络使用平滑曲线。提前铺入低能量素材时，通过频段和音量保留出碟高潮的主导地位。
- 持续音与人声活动检查用于避免正在发声的中间硬切。不是强制播完整个 Verse；可使用测得的间隙、EQ 和渐退控制双前景冲突。证据不足时不会把“没检测到人声”当作无人声。
- 出碟人声未释放（`voice_released`：切点处有可测呼吸/间断、唱音正好落在边界上结束、或切点后约 0.4 s 内活动低）的位置，不允许放瞬切、DropCut 或桥接类结尾。唱到边界前一瞬才停是合法切点，不要求切点前先行安静；人声延续过切点才阻止。用户显式 OUT Cue 例外。
- 对整段重叠检查网格、tempo、局部调性、频段和前景风险；额外比较移调后的 Chroma 进行及持续冲突。Chroma 是混合音频的音高分布，不是已识别的乐谱或 stem。
- 双碟都有可用 stem PCM 时，按实际频段能量搜索两侧人声、鼓、乐器、低音的独立时间曲线。可保留出碟人声或节奏覆盖入碟，由通道 Level、crossfader 和声部比例共同控制最终路由包络。人声只在完整测量支持的停顿中退出；短音符不单独证明连续演唱可以被切断。此类计划标记 `requires_stems`；引擎在两碟声部未就绪时拒绝执行，宿主随即按保守方式重新规划。
- 顺序交换旋律声部时，进一步比较独立淡入曲线及通道 EQ 的声部补偿，以实测伴奏能量和控制变化速度选择包络。另一碟仍有旋律、人声或低音时不抬高这一声部；人声、鼓、低音的实际增益保持不变，通道补偿上限 6 dB。最终乐句保护仍然有效，下一次规划继承调整后的真实入场位置。候选最终扣分后必须仍优于已有方案，初评分不能替代实际编排评分。
- Loop 需要稳定网格、鼓与前景证据，并量化释放；Echo/Filter 由声音和结构需要决定，不以特效数量加分。低置信度网格不能通过放长混音或堆叠 FX 变成可靠对拍。
- 出碟退出落在自身下一个 Drop/Chorus 开始前 8.5 小节内、且退出点本身不是高潮结尾时，只有 build-up 交换成立：入碟高潮起点必须精确落在交接点（叠混/LoopRoll 为 `b_end`，瞬切为 `bin`），否则该候选被否决。有完整声部编排时，入碟高潮可以在重叠区间内开始；按到达后一个完整源小节内实际路由的总体与前景能量判断，不要求安静声部的名义推子同时到位。出碟携带的人声或鼓可参与承接，但持续移除前景仍会被拒绝。其他路径仍要求它落在 `b_end` 或之后。
- FilterSweep 叠混上限 16 小节（一侧为纯打击乐时除外）；旧式跨调声部包络限制在 8–32 小节；更长窗口必须通过独立声部拟合和有音高声部完全分离检查。
- `drops::peaks` 忽略短于 3.5 小节的 Drop/Chorus；`major_peaks` 要求 ≥7.5 小节且中位 RMS 不低于最响高潮约 −1.2 dB，用它计算"主体高潮已播完"罚分，退出早于曲目 40% 时另加提前退出罚分。出点候选保留范围从曲目 25%（上限 60 s）开始，用户 OUT Cue 例外。
- 高响度、强限制器的录音可以在连续 Drop/Chorus 内有相对恢复。共享的 `relative_recoveries` 比较前后完整邻域的鼓分轨功率及攻击活动，要求持续退让超过局部波动、旋律底床仍在、节奏随后恢复。它保留原有粗结构标签，只在派生高潮范围和恢复候选中分开这个窗口。窗口的起止是编排变化证据，不给内部每条小节线创造乐句结束，也不授权撤出仍在继续的人声或旋律。没有既有完整乐句边界时，只有最终分声部编排成功才允许在窗口退出，短交不能借用这项许可。相对起伏的返回也不自动算作额外一段高潮扣分。短 fill、单独低频撤出、整体淡出、蓄势、弱时钟和缺失测量不能取得该许可；没有有效 stems 时保持原保护。测量只在不可变规划输入的借用期内缓存，不写入分析数据库或音频 callback。
- set 的 `owed_peak` 比较第一个完整、足够强的 Drop、原有 `main_peak` 与 `released_peak`，取较早者；不强制再播放第二段 Drop。完整高潮会减轻但不抹去短驻留代价，避免“进来很快就退出”。进入按入碟实际发声内容建立的位置计起，退出看旋律前景开始离场；安静的人声或低音控制不延迟入场，尚被压住的旋律和演唱仍会延迟。静音播放头和单独鼓层不能抵充主体播放时间。较弱的早期 Chorus 不自动满足要求。`released_peak` 要求完整进入、结尾的实测变化、完整恢复乐句，以及至少 3 dB 的总体回落、6 dB 的低频回落和至少三分之一的节奏活动下降。短 fill、抽低频但节奏持续、静音、缺失测量和仍在 BuildUp 都不能满足。该策略不改写自动 cue，退出与声部交接仍通过原有安全检查。
- 有界跨度搜索在原有候选之外保留最多八个入碟高潮落点、八个较近的可行跨度和八个出碟编曲起点，总数不超过 36。增加候选不放宽节拍、调性、人声和源时间检查。
- **Spinback**：出碟末半小节加速回拉的 backspin 停碟（`ScratchOp.accelerate`），低通收至 2.5 kHz、低频与增益同步关闭，入碟在其自身 Drop/Chorus 起点落下。要求双网格可靠、乐句对齐 ≥0.75/0.6、出碟末段 kick ≥0.5 且人声 <0.5、入碟 kick ≥0.55。确定性轮换：与合格 DropCut 竞争时约 40%，无竞争约 70%。
- **LoopOut**：BeatBlend 的 4/8 小节窗口中，出碟循环其开头 1–2 小节并被逐层抽离——人声 1/4 小节内归零、乐器在中点前归零（双碟 stem 就绪时用声部包络并标记 `requires_stems`，否则用 −12 dB 中频与 −6 dB 高频）；低频在中点交接，结束时释放 loop 并关闭出碟。约 1/3 合格叠混启用，条件含入碟结构为 Intro/Break/Breakdown 或其高潮恰好落在 `b_end`。
- 技法轮换（Spinback、LoopOut 以及 Echo/Filter 结尾互换）由 `(曲对 id, 退出点, 进入点)` 的确定性哈希决定：同一输入永远得到同一策略；Outro 结尾保留 Echo 不换 Filter。

Key lock 只负责变速时保持音高，不自动保证两个片段的和声相容；局部 key、移调及重叠音符检查是另外的规划步骤。出碟从实际 rate/pitch 开始，入碟先静音同步，再按共同速度曲线迁移；恒速歌曲完成后可恢复入碟原 BPM。支持半/双倍拍映射。可信局部调性需要修正时，按实际 sounding key 选择入碟移调，绝对偏移限制在 ±2 半音（`score::MAX_KEY_SHIFT`）。第一个半音只有轻微代价；第二个半音在候选评分和前瞻中另计明显代价（`score::shift_cost`），只在其余方案更差时使用。两个半音内无法相容的调性保持冲突，由分离有音高声部、滤波或乐句交接处理，不再移调。重叠内保持音高；独奏时结合后续曲目，在低人声、低能量且有完整测量的窗口中，用平滑曲线配合 filter/EQ 恢复全部或部分原调。没有安全窗口就保持偏移，下一对继承实际状态。源音频默认做响度标准化，规划器不再用接点附近安静 intro 的 RMS 任意放大整首歌。

曲速不同也可做长混：先选择最接近的原拍、半拍或倍拍关系，再求两碟各自 ±8% 绝对速度及当前偏移的交集，再于入碟静音期间准备共同速度。若普通范围没有交集且双碟声部可用，可尝试各自 ±12% 的有限范围；最终必须实际使用分轨编排。全程遵守对数速度变化率约 0.35%/s 的上限。若混入长度容不下回原速，入碟先保持匹配后的速度，重叠结束后在独奏中按同一速率上限滑回原速（`tempo_recovery`，阶段名 Restore tempo），12% 约需一分钟。仅当下一首需要同方向调整时保留一部分：取两碟相向各让一半的位置，最多 6%，且不超过当前偏移。回原速最多占用曲尾保留段之前剩余时长的一半，不足时只恢复一部分。该滑动写入已提交的时钟，下一对从实际到达的速度规划；前瞻在预测下一对之前先为每个候选完成回速，并对计划结束后仍保留的移调与速度偏移按剩余播放比例计入代价。用户显式设置的入碟速度作为基准不被恢复；`prepared_handoff` 为下一对预设的速度不被撤销。

重叠期间入碟保持恒定速度（hold）且该速度对应的自然音高（12·log2(rate)）与调性所需移调相差不超过 10 音分时，计划标记 `incoming_varispeed`：入碟以关闭 key lock 方式播放，不经过变速拉伸与移调处理，`pitch_b` 只保留显式调音，实际音高由 `MixPlan::incoming_pitch_at` 给出，`incoming_offset_end` 已包含它。条件由 `varispeed::fit` 判定：需要可靠调性、入碟无显式调音、重叠内速度引起的音高漂移不超过 5 音分、自然音高在 0.5 至 `MAX_KEY_SHIFT` 半音之间；原调已相容或锁定方案移调更小时保持锁定。此类计划的回原速不保留偏移，音高随速度一起回到原调，独立的回调步骤不再处理它。引擎按该标记设置入碟 key lock，出碟始终锁定；计划结束且入碟回到原速时重新锁定，否则保持解锁以免音高跳变；滑动中按 SKIP 保留已到达的速度与音高。若只能完成当前乐句后瞬切，可在入碟静音时预设有利于下一首的有限速度偏移，避免下一首刚进场便错过第一个完整 Drop 的出口。

声部编排使用三组分析频段，乐器低频作为低音的估计，不把它称为独立第四组测量。按人声或主旋律决定中高频主导方，背景频段仅衰减，最多 12 dB，变化不超过 1 dB/s；独立鼓层按另一碟低音的占用进行高通。最终同时检查 Level、crossfader、EQ、filter 与 stem 增益，拒绝在持续演唱中撤掉主唱，或在出碟高潮尚未结束时持续丢失超过约 3 dB 的能量。手动 OUT 保留原有权威。排序缓存版本随旋律退出包络和人声语义等规划行为更新。

对已对拍的顺序声部交接，若入碟所有有音高声部在出碟旋律淡出期间保持关闭，出碟旋律可使用较慢的功率衰减，保留尾音至原定乐句出口。只调整出碟 channel/stem 增益，并反向补偿其他三声部；不改变 crossfader、入碟控制、源时钟、速度、音高或退出点。旋律不超过其原始全开音量，channel 不超过现有 6 dB 上限，最终仍通过人声和旋律保护。原速非对拍桥接、旋律重新进入、手工 IN/OUT、缺失 stems、循环和 FX 不套用这一调整。它减少淡出中的伴奏空洞，不把曲尾退出重新包装成更早的交接。

人声保护区分可听的演唱主体、同一音符的安静尾音和缺少主体佐证的弱音符估计。前两者及句内短停顿继续作为硬约束；弱估计保留风险扣分，并优先使用证据更完整的入口。已有完整人声的小幅电平恢复不等于从半句话淡入。人声入口本身已经完整时，可在实际启动时开放声部；是否冲突取决于实际同时演唱，而不是两个推子是否同时开启。

局部 vocal chop 由共享的 `vocal_pattern` 证据判断：人声分轨的能量包络、频段比例和短音符序列须在多个周期内共同重复，切换点本身也须匹配。短音符密集或节拍规则不单独证明是切片。明确重复的片段可以作为节奏声部渐入渐出，单个切片内部仍不能作为硬出入点；有叠加唱句、持续长音、变化中的音节或证据不足时保留唱句保护。识别不取消局部和声、实际能量、网格和完整高潮检查，也不把整首歌标成 chop。它读取现有 stems 测量，不增加持久化分析字段；规划缓存仅在当前输入借用期间有效。该规则自 `ORDER_VERSION=26` 起使此前的旧排序失效，当前排序版本见前文。

器乐分析使用共享的 `instrument_voices` 和 `instrument_boundaries`：按音高距离、起音时间、延音与旋律走向联合连接声部，允许音区交叉；不把最高音固定视为主旋律。动机候选需要三轮完整重复，并由每个活跃声部独立支持，重复低音不能掩盖仍在发展的上层旋律。上一组释放与下一组起音分别记录；休止还须有分轨功率退让，转录空洞不算休止。已恢复这些证据参与器乐渐变搜索，结构和音符候选分别保留预算；可听渐变仍满足原有局部最短时长，实际安静窗口可以用于较快揭入。证据不授权整轨硬切，最终仍检查人声、高潮、节奏与和声。BEST 链路评分已修正首条边冷启动与闭环重复计分。多声部追踪不等于完整音乐语义识别；Brain Power 尚未获得新的全器乐安全出口，跨歌单结果仍有待试听项。独立审计按单个音符区分起音隐藏、尾音衰减和控制变化速度，旧的重叠长音合并计数仅保留作描述。

分轨候选以编排后的实际人声重叠判断冲突。搜索时先使用成功编排可达到的评分上界，编排失败恢复原始冲突扣分；不能仅因为原始两首都有人声而提前排除分时交接。重复检测不是语音识别：现有三个频段和音符证据无法保证区分所有同音高短唱词，长周期或变化中的切片也可能保持未知。回归须分别记录累计空缺、连续空缺和真实渲染，不以短交数量或单个代理指标断言听感。

延迟启动的入碟在启动前不贡献可听能量。候选继续检查最终声部路由和能量连续性。BEST 对曲尾短交接的惩罚使用最终增益、EQ、滤波与实际启动时间计算可听重叠，不再把名义预留小节数当作叠混。独立全歌单评估继续报告人声损伤、可听叠混、曲尾短交接、伴奏空档、节奏、和声与音高，不以单项计数或离线渲染代替听感验收。

声部拟合分别保留附近最多四个结构窗口与四个音符窗口，比较实际生成的控制曲线；先通过前景保护，再按原有拟合代价与最终能量损失选择。最终损失只扣分一次。能量比较按每首录音自己的活跃功率归一化，在完整本地小节内积分，避免单个瞬态抬高整段评价；弱入碟素材适用约 3 dB 的损失预算，完整入碟素材逐渐放宽至原有交换预算 6 dB。另检查交接后一小节，未改变出碟的自然低潮与手动 OUT。未交换的预备播放不稀释平均损失。循环路径仍不使用这项新代理评分，缺失证据不产生惩罚，也不等于质量通过。固定两首歌没有好候选时，BEST 可以更换邻接关系；不会为消除应急次数而放松人声、乐句或调性保护。

原速桥接也检查鼓之外的节奏：拨弦、琶音、切片人声和脉冲低音不能因为关掉鼓层就视为无拍素材。不同源时钟下，两个可听见的节奏前景不能同时铺开；缺少安全交换时退回更短的接点。乐器层的引入另外计算每秒增益变化，避免大声和弦被短淡入突然揭开。

安静前奏或低潮的弱起网格不足时，可尝试其后四个小节内首个可靠下拍，且必须保留至少四小节的测量窗口。这只授权实际完成的分轨编排，不生成新的乐句边界，也不授权整轨瞬切；手工 IN 仍优先。

声部搜索另保留不同呼吸窗口与独立的旋律交换位置，避免大量相邻帧耗尽候选名额。鼓、低音和旋律不必在同一时刻交接；出碟只剩鼓组时，不再把它视作上一段旋律仍在主导。实际演唱、延音、局部调性和整小节能量保护仍有效。后半首的 Break/Breakdown 及相对恢复也可以提供入点，但必须还有完整高潮可播，且不能挤掉原有前奏候选或覆盖手工 IN。

前瞻保留最多三个不同的已建立入场乐段，结合原调及保持速度方案，用真实的后续曲对规划比较当前与下一次交接。后续规划继承实际入点、结束时间、速度、音高和 Cue，不递归展开整张歌单。独奏回调必须给已找到的下一次退出留出时间，不能为恢复原调而把下一对挤到曲尾。搜索扩大后准备耗时增加；尚未找到好方案的曲对继续作为待改进项，不由安全检查通过或名义长度判定听感合理。

候选剪枝、短名单、前瞻与 BEST 共用短切和曲尾短交接代价，避免先按原始分数删除重叠方案、随后才在排序阶段扣短切分。具备源时钟和 stems 时，曲尾位置以最后实际可听的出碟内容计，重叠按未经时间平滑的声部测量计；孤立鼓击不会填满两次击打之间的空档。持续撤掉仍在播放的前景另有按局部小节累计的代价，长静音准备不能稀释它。自然 break 和接管前景的人声保留。三个入场短名单名额中，为仍能完整呈现较早主体高潮的最优方案保留一个位置，防止较晚乐段的移调变体挤掉它。BEST 的链路修复识别普通晚出 DryCut，以及连续至少一个 master 小节的前景空缺。累计缺失达到一个小节时，也检查完整小节的前景是否退让超过已有的 6 dB 预算，避免短促峰值反复重置连续空缺计数；整小节前景仍在的零散短空档和孤立 impact 不因此触发。这些是修复目标，不新增 pair 硬拒绝条件；循环与缺失证据仍保守回退，不能据此宣称已完整观测。

## 分析与执行边界

`mixless-analyze` 生成源域 beat/downbeat、逐 bar 响度/频段/kick/Chroma、结构边界、多组进出区域，以及 50 ms 的持续音/前景/起音证据。当前 `ANALYSIS_VERSION=27`，桌面默认追加原生分轨和音符证据。拍速搜索覆盖 70–240 BPM，使用小数自相关 lag，并扣除更快网格自然捕获更多瞬态的背景期望。局部时钟只在连续窗口的周期与相位证据一致时细化，插值区间重新计算可靠度。鼓组持续撤出而合成器保持响度时，共享声部退让判据可补出低潮入口 cue 和候选区域。拍号候选比较 3/4/5/7 个脉冲的重音均值、跨小节重复性与候选分离度；非四拍还要求前后半段一致。证据不足保留低置信度的四脉冲假设，不能据此宣称下拍准确。结构标签仍有歧义，不能保证每首歌的 drop、下拍或 key 都正确。

macOS SoundAnalysis 是可选的系统声音分类补充；默认有时间预算，失败回退至 DSP 分析。它不分轨，也不输出音符。[Rust 原生模型链路](native-inference.md) 默认在后台分离 vocals/drums/instruments，提取音符并写入分析缓存；AutoMix 用它定位人声间隙、保护长音、比较音符进行与低频冲突。[独立声部实时混音](stem-playback.md) 提供四声部增益及可选的 AutoMix 声部包络；只有两碟匹配的 PCM 都准备好时执行声部包络，否则继续使用整轨 EQ/filter/Level 方案。

后台规划生成不可变控制曲线；宿主编译为每 32 个设备帧的控制点，音频线程只执行，不查询 SQLite、不分配模型、不做推理。计划和预览带列表版本，重排、改 Cue 或重新分析后刷新，避免显示上一对的窗口。

## Live moves（过渡期外的实时动作）

AUTO 正常播放期间，`mixless_mixplan::performance_moves` 按分析为出碟安排两类小动作，由 `live_moves` 偏好（Off / Subtle / Active，默认 Subtle）控制：

- **滤波渐升**：对止于高潮起点、且具备 build 证据（BuildUp 标签、`has_buildup`、或末 4 小节 onset density ≥首 4 小节 1.2 倍）的段落，在其最后 4（Subtle）/ 8（Active）小节把通道滤波从旁通升至高通约 400 Hz（`amount` 0.405；窗口人声偏强时用 60%），在高潮下拍前 5 ms 回到旁通。
- **鼓声部抽离**：≥16 小节的主要高潮内，在 8 小节边界的前一拍把 drums 静音并在下拍瞬间恢复（需出碟 stem 就绪；Subtle 只用最后一个合格边界，Active 用全部）。

动作要求整个窗口网格可靠，且完整落在"播放头 +0.5 s"到"过渡开始前一个拍"之间——放不下就整个放弃，绝不截断半个扫频。宿主 `Performer` 经 `Engine::perform` 下发，不写计划的 lane 接管标记；用户在任一 lane 上的手动操作使该 lane 在本曲内永久交还；动作结束、过渡开始或 AUTO 停止时把仍在动作中的 lane 恢复中立值。

## 验证入口

跨版本比较使用独立的 [离线评估器](../../scripts/automix_eval/README.md)：同一参考证据重算旧版、新分析加旧规划器、新版，分别检查固定顺序和重新生成的 Best 顺序。指标包含实际可听重叠、局部对拍、移调后声部音符、人声衰减与跨界持续音、持续高能量段损失、中高频前景重叠、乐器控制突入、整组音高负担和完整 Drop 后等待。计划自身的 `score` 不作为独立质量指标；静音准备和独奏回调不算混入。

评估器当前为 v7：源时间按实际 rate/clock 与启动位置推进，出碟停止以实际交接小节为准。前景与能量损失以出碟自然延续为参考，不再把尚未听见的静音入碟当作已经丢失的声音。两版计划必须用同一评估器重算。混合期间空缺仍有观察窗口限制：零小节硬切没有混合区间，比较它和长叠混时须另看同等出点后上下文及真实渲染。数值校正不代表规划器或听感改善；最新完整对照与保留的警报见 [复音追踪记录](../history/2026-10-27-instrument-voice-leading.md)。

评估器另输出 `realism`：每个过渡按结构、变速、移调、交接后保留的速度与调、曲尾放完、对拍、和声、人声与能量九项检查计 0–100 分，每项按通过 strict / default / lenient 的最严一档得 1 / 0.8 / 0.5 分，default 档无任何偏离的过渡另得 40% 的干净奖励，有缺陷的过渡保留已通过项的分数。歌单可以是任意曲目与顺序：变速只评判超出该曲对拍所需的部分，原调冲突时多容许一个半音；这项宽限只到重叠结束为止，之后仍保留的速度与移调另行评判，曲目放到曲尾且几乎没有叠混的交接不算干净。未观测的过渡不计分并给出上下界。另把每首已播曲目的变速与移调同真实 DJ 混音统计（Kim 等，ISMIR 2020，1,557 套混音）逐项对比，这部分不设宽限也不进入得分。定义、分值与适用边界见[评估器说明](../../scripts/automix_eval/README.md#dj-practice-comparison)，首次结果见 [DJ 实践对照记录](../history/2026-11-10-dj-realism-indicator.md)。分值与阈值未经试听校准，不是听感验收。

各项同时报告覆盖率、暴露时长和阈值敏感性。鼓活动强度的突变与网格对拍分开计算，避免把节拍一致视为节奏型变化自然。循环／scratch／insert 等无法还原的路径标为未覆盖，缺少人工标注时不报告 cue 准确率。三频段功率与参考网格均为代理测量，不能替代 PCM 对拍验证或主观试听。各 set 分开比较，并区分安全检查带来的短切与仍可改进的混音退步；已用于调试的录音不能作为 holdout。本次对照结果见[跨 set 评估记录](../history/2026-10-17-cross-set-evaluation.md)。

```sh
cargo test --locked --workspace --exclude mixless-desktop
cargo test --locked -p mixless-desktop
cargo test --locked --release -p mixless-engine callback_budget -- --ignored --nocapture --test-threads=1
./dev.sh --build
cargo run --locked --release -p mixless-analyze --example automix-real -- outgoing.wav incoming.wav preview.wav
# 库副本离线审计（不改线上库）
cargo run --locked --release -p mixless-library --example reanalyze-copy -- LIBRARY.db OLD_VERSION NEW_VERSION
```

测试包括零小节瞬切、临近边界才开启 AUTO、自然 EOF 接续、24/48/64 小节分层混合、移调后的进行比较、播放列表重复条目/刷新/退出保存，以及计划波形映射。真实曲对渲染检验完成交接、采样有限性和输出范围。连续 `render-set` 必须按桌面逻辑复位复用碟盘，逐次检查输出信号和入碟控制已打开；单有时长、峰值和播放头完成不算连续可听证据。2026-10-24 审计已更正旧渲染的静音缺陷并重跑四个原音频齐全的列表。上述检查不能替代主观试听或原生界面操作验收。
