# 波形拖拽与自动对拍

调研日期：2026-09-05。以下商业软件行为来自官方文档；其内部算法未公开。
Mixless 的控制算法是独立实现，不能据此声称复现其专有分析技术或同等听感。

## Mixless 当前行为

横向波形向右拖、竖向波形向下拖，都让源时间后退，使抓住的内容随鼠标移动。
比例与当前绘制窗口使用同一个源帧／像素计算，播放线固定。全局事件继续接收
控件外的移动和松手；空碟不接管。拖拽沿用低延迟 scratch 路径，松手提交最后
目标位置，保留原来的播放／暂停状态。启用 Slip 时保留原有后台时间线返回行为。

在从碟点击 SYNC（或选中后按 S），另一碟成为 MASTER。引擎同时同步速度和
拍相位；再次点击退出，保留当前速度。暂停碟只准备同步，启动时才进行相位对齐。
分析尚未完成时点击 SYNC 会记住本次双碟曲目，显示 SYNC …，分析完成后自动
启用对拍，不必再次点击。再次点击可取消等待。等待期间换曲、卸载、搓碟、
从碟调速或启动 Automix 都会取消请求；没有有效节拍网格则显示失败原因。
键盘 S、鼠标和 MIDI 的同步操作使用同一入口。手动 SYNC 同时取消后台 Automix
规划任务，避免任务稍后发布过渡计划覆盖用户的同步选择。
主碟调速后从碟持续跟随；从碟调速、任一碟抓取波形／jog 或反向播放会解除同步。
Cue 跳转和暂停恢复会重新对齐。卸载／换曲解除关系，避免跟随旧曲。
手动 SYNC 接管 Automix；启动新 Automix 计划则解除手动 SYNC。

界面状态来自音频引擎：MASTER 为参考碟；SYNC … 表示准备／校正中；填充绿色
SYNC 表示两碟在播放且网格相位差小于 0.02 拍。GRID … 为后台分析中，NO GRID
为没有可用网格。缺失、过期缓存会在工作线程重新分析；分析失败会显示错误。
分析版本 4 不再给静音或缺乏节奏证据的音频发布虚构网格。

## 实现

`crates/mixless-engine/src/engine_sync.rs` 持有源时间秒数的节拍数组。对当前位置
做二分查找，在相邻拍之间插值，得到连续拍位置和局部拍间隔。令两碟局部拍间隔
为 `Tm`、`Tf`，主碟速度为 `rm`，则从碟名义速度为 `rf = Tf / Tm × rm × k`。
`k` 从 1、1/2、2 中选择最接近从碟原速的匹配，激活期间保持不变。

拍相位误差为 `wrap(masterBeat × k − followerBeat, −0.5, 0.5)`。
激活／启动／cue 时，使用现有 6 ms seek crossfade 对齐最近拍相位；后续以
最多 ±2% 的临时速度修正消除漂移，不在每个回调反复跳转。名义速度与校正分开，
避免控制量反馈到自身。开启 Key Lock 时沿用 Signalsmith 的变速保调路径。

控制器在音频块边界运行，使用引擎播放头；界面不积分时钟。网格验证和分配在
主机线程，callback 仅 `try_lock` 和二分查找，锁争用时继续播放并在下个块重试。
只有一个从碟 ID，不会出现相互追赶的循环依赖。网格带 track ID，换曲后失效。

## 验证与边界

离线回归覆盖不同首拍偏移、44.1/48 kHz 源文件、持续主碟调速、半速匹配、
局部速度变化、主从切换、暂停启动、cue、scratch 接管、回调间完整拖拽手势、
无效／过期网格和网格锁争用。另比较两碟实际渲染脉冲，检查经过保调变速后
瞬态时间差小于 10 ms。稳定段传输测试要求相位差小于 0.004 拍。
`crates/mixless-analyze/tests/beat_sync.rs` 还覆盖真实 WAV 文件生成、离线分析、
加载和双碟渲染的完整路径：123／128.5 BPM、不同首拍偏移及 44.1／48 kHz。
验证使用生成音频的实际鼓点时间计算误差，不依赖分析器自身网格作判据；
持续播放的相位误差上限为 0.025 拍。桌面测试覆盖等待两碟分析、分析失败、
换曲和手动接管时取消请求。

当前为单拍相位同步，不承诺小节首拍或乐句自动对齐。传输层可读取可变间隔网格，
但离线分析器目前仍拟合全曲固定 BPM；真人鼓、明显变速歌曲需要进一步的动态
节拍检测及网格编辑能力。网格锁定只说明播放时钟跟随该网格，不证明分析网格
与音乐中的鼓点准确重合。现有 loop 使用全局 BPM 定义长度，动态网格的循环
边界尚需专门支持。

自动化验证环境为 macOS 27.0（26A5425a），无音频设备的离线渲染；桌面使用
Xcode-beta 构建。没有在本次工作中测量实体设备拖拽延迟、帧时间或进行人工试听。
