# 独立声部实时混音

2026-09-14 接入。分轨推理仍在 Rust 后台完成；实时路径只处理已载入且与原曲版本一致的 PCM。

## 音频路径

`原曲 + vocals/drums → 声部增益 → 共享重采样/变速移调 → 通道 EQ/filter/FX → PFL/Master/内录`

三个声部使用同一源位置、Cue、loop、反向和 scratch 时钟，以及每碟一个 MusicStretch。没有三个独立变速器，也没有实时模型推理。三声部全开时直接保留原曲，连贯的整数 PCM 读取保留快速路径；变速输出完全接管后跳过不用的原速重采样。

采用残差归入 instruments 的组合：`gI × original + (gV − gI) × vocals + (gD − gI) × drums`。这样全开严格还原原曲、全关静音，也少保存一条 PCM。instruments 包含模型重构残差，可能带有泄漏；不能称为完美隔离。沿用原曲统一响度增益，不逐轨重新标准化。

声部控制具有 150 ms 平滑。变速路径还包括已有的预读/合成窗口延迟；声音不会为了更新声部控制而重新 seek 或重置变速器。FX 目前处理声部合成后的通道，未添加每声部独立 FX 机架。

## 桌面和 AutoMix

每碟的 VOCAL / DRUMS / INST 旋钮竖排放在 SYNC 控制区下方，名称标签居中放在旋钮下方，不显示百分比；整列与曲速推子共用相同高度并均匀留出间距。A/B 控制区镜像排列，SHIFT 和曲速推子靠外，SYNC、KEY 与声部控件靠内。支持连续增益，点击文字切换开关，双击旋钮恢复全开。PCM 未准备好时隐藏声部控件，继续播放原曲。曲速推子位于 SHIFT 下方，使用细轨道、较宽的拖动区域，并填满该列剩余高度。模型完成或读取有效缓存后，后台加载对齐声部；首次手动上碟仍先发布可播放原曲。

AutoMix 在已有合法混音窗口内，为检测到的双人声、双鼓低频与持续音符冲突生成可选声部包络，参考实际音量交接和人声空隙。只有两碟都已加载对应 PCM 时才执行这些包络；否则保持原来的 EQ/filter/音量方案。瞬切不会因为新声部功能被改成长混音。单独操作某个声部只接管它的包络，停止 AutoMix 保留当前手动状态，下一首载入恢复全开。

## 资源与回调约束

- PCM 文件读取、校验、重采样和分配都在加载/分析工作线程，不能等待全局推理锁。当前每碟声部 PCM 上限 512 MiB；超限保留原曲播放。
- 源 Arc 身份、帧数、采样率与桌面内容 hash 同时约束发布；同 ID 的文件换版也不能将新 stems 接到旧音频上。
- 回调只尝试获取发布锁，竞争时继续使用已持有的数据。原曲和声部替换后由 host 保留并回收，避免回调释放大型 PCM。
- macOS `std::Mutex` 首次使用会分配 pthread 存储，所有回调可见锁在开启流之前初始化。
- 分轨推理队列独立且单任务，CPU 推理两线程、utility QoS；没有在本轮新增 Python 依赖。

## 验证

行为测试覆盖全开输出一致、隔离人声与参考音频一致、Cue/loop/reverse/keylock 的同源时钟、失效数据/锁竞争、全关静音、AutoMix 就绪回退和单声部接管。

测试分配器覆盖 Rust 分配、释放和 realloc，包括首次 callback、Cue 及卸载；不拦截原生 C++ 运行库的内部 allocator。性能验收使用 release 双碟声部、变速移调、Reverb、内录和频繁双碟 Cue，并另外执行真实 ONNX 推理与已分轨双碟播放的并行测试。当前结果见 [验证记录](../history/2026-09-14-stem-playback.md)。
