# Mixless Audio Analysis

把用户报告的曲目用于定位机制错误，产出能解释、能验证、不过度依赖这些曲目的分析改进。适用于分析算法及其在 cue / AutoMix 中的消费；纯界面、打包或文案修改不需要运行音频验证流程。

## 建立证据

- 先确认当前源码、音频内容哈希、分析版本、是否使用 stems 和 cue 来源。旧审计副本不能代表当前正式库；旧报告不能代表本次实测。
- 沿“音频 → tempo/grid → moments/bars → section/phrase → cue/region → pair plan → playback”定位错误所在层。记录时间坐标、单位与局部节拍，避免在规划器里补偿未经确认的分析错误。
- 区分原始观测、语义推断和混音策略。RMS 降低不直接等于 Outro，section 边界不直接等于安全出口，强瞬态不直接等于 drop。结构标签也不能拿来独立证明生成该标签的规则正确。
- 判断停顿、蓄势与恢复时查看前后持续上下文，组合响度、频段、节奏活动、持续音/人声和真正的重启；保留“尚不能确认”的可能。

## 防止过拟合

- 生产规则不按曲名、track ID、歌单、报告中的秒数或某一首的固定编曲分支。实曲时间点可作为明确标注的回归检查。
- 每个新条件说明它对应的音乐或信号机制、测量单位、证据不足时的行为及会误伤的反例。新增阈值需要依据；把一个常数换成另一个常数不是泛化证明。
- 秒数、小节数、BPM 与半速/倍速解释不是同一个尺度。优先使用局部时钟和相对邻域；保留必要的时长上限时，把它视为候选搜索或策略边界，不能单凭它认定音乐事件。
- 实现和测试都要有反例：例如短而完整的 breakdown、只有 bass mute 的持续鼓段、长静音、一次 impact、没有恢复的尾奏。不能只生成一批满足新规则的正例。
- 对目标语义应保持的变换做验证：合理增益、整体时间平移、速度变化、等价半速/倍速网格。明确变换的是测量数据还是重新解码的音频；前者不证明特征提取本身具有不变性。拍号、变速、弱网格与缺失 stems 按本次改动影响选择覆盖。
- 在调整参数前划分开发曲目与未参与调参的评估曲目，按完整录音/相关版本隔离，不按同一首的片段拆分。已查看并据此调整规则的曲目归入回归集；不能继续称为 holdout。
- 有代表性的独立样本不足时，完成现有回归与反例检查，并如实限定结论。禁止用“27 首都能出计划”等数量替代跨风格准确性证明。

需要设计验证集合或记录验收证据时，读 [验证规范](references/validation.md)。

## 接入与验收

- 共享音乐语义放在公共实现中，自动 cue、mix region、恢复窗口与规划器不要各复制一套判断。自动 Out 是通用建议，pair-specific 的合法交接可能不同；不强制它们拥有同一个时间点。
- 保留用户显式 cue 的原有权威；只刷新自动 cue。改变持久化分析语义时处理版本失效、重分析与加载缓存，旧分析缺失特征时不能放宽安全约束。
- 用数据库一致性副本做审计。结构刷新不得改变原始 grid、重复加权已有 stem 证据或混淆版本。源音频、个人库、数据库和渲染产物不提交到仓库；可保存必要的数值特征和来源说明。
- 分别评估结构准确性、cue/计划行为和渲染正确性。计划成功与音频无削波只证明该层检查通过；听感、原生 UI、物理播放与实时性能各需要相应证据。
- 完成与改动相关的测试及仓库规定检查后停止重复跑相同验证，除非新改动、失败或未解决问题需要复核。分析和 I/O 不进入音频 callback。

在 Mixless 仓库执行时，按需读 [代码与审计入口](references/mixless.md)，并以当前实现和仓库指令为准。此 skill 不额外授权下载、发布、修改正式库或中断播放。
