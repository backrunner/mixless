# 音乐分析改动的验证

## 先写可证伪的判断

用音乐含义定义错误及预期，例如“已经开始的蓄势不能在恢复前被普通淡出消耗”，而不是“这首 60.58 秒不能退出”。同时列出可用出口为何仍应可用，避免通过拒绝所有过渡使错误率归零。

先固定要检查的指标、容差和曲目角色，再看候选规则的结果。人工标注写成事件范围、允许误差和置信度；drop 的第一击、build 开始、静音边缘可以使用不同容差。现有算法标签是基线，不能自动作为真值。

## 验证集合

| 集合 | 用途 | 不能推出的结论 |
| --- | --- | --- |
| 用户报告的录音 | 重现缺陷、寻找机制、精确回归 | 对其他编曲泛化 |
| 正例与难反例 | 区分想保护的音乐事件和正常混出 | 真实音频质量 |
| 受控变换 | 检查增益、时间坐标、速度、节拍解释等不应改变的语义 | 未重新提取时的 DSP 稳健性 |
| 未参与调参的录音 | 评估新规则对不同曲目和编曲的影响 | 未覆盖曲风、设备或人群 |
| 真实规划与渲染 | 检查候选可达、源坐标、交接完成、有限值和削波 | 乐段标签正确、主观自然 |

按改动选择音乐维度：有/无人声，稀疏/密集编曲，强限制器/大动态，规律鼓点/切分节奏，短 fill/完整 breakdown，drop/chorus/无明显高潮，弱起/变拍号/变速。不要为了填满表格伪造未持有的样本。

同一首的 remaster、edit、重复文件、stem 版本和前后片段应留在同一集合。首次评估失败后可以继续改进，但已经暴露结果的集合此后是开发或回归材料；寻找另一批独立录音，或声明缺少独立验证。

## 按层记录，而非只报通过数

- 检测：漏检、误检、边界误差及人工可接受范围；候选变化是否来自 grid 漂移。
- 语义：蓄势被拆断、把 impact 当 drop、把节奏持续的短 break 当停顿等具体错误；对语义有争议的片段保留不确定性。
- cue / 规划：自动出入点变化，提前丢弃高潮，非法重叠，手工 cue 是否保留；同时记录无计划率、过晚曲尾回退和安全过渡被拒绝的比例。
- 渲染：所用源码和分析版本、源时间/采样率、策略及是否真的播放 stems；有限值、峰值和交接完成。需要评价听感时试听前后音频，不从数值“推导已听过”。

阈值改动检查合理邻域内的敏感性，尤其是阈值两侧、低置信度和特征缺失。差异若集中在一个极窄数值附近，应回到信号机制和标注复核；不要持续调参直到所有已知例子正好通过。

## 最小记录

每次实质性算法改动留下：

- 机制假设、反例及其预期行为。
- 样本角色和覆盖范围，分析/源码版本、可重现入口、标注来源。
- 改前/改后差异，误拒绝与回退影响，未解决或有争议的片段。
- 单元/变换/实曲/渲染/试听分别完成到哪一层。

Take You Home 与 Day Cycle 是停顿缺陷的开发样本。它们的时间点或这次修复使用的阈值不是后续所有歌曲的标准答案；已有 DnB 和 melodic set 的检查也不能代表未测过的 pop、acoustic 或其他曲风。
